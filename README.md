This repository contains the core hardware-accelerated vision firmware for the **A.E.G.I.S. (Autonomous Emergency Ground Intelligence Swarm)** project. 

It is engineered to run a natively quantized **YOLO-Pro Pico** object detection model directly on an ESP32-S3 microcontroller. By bypassing standard TFLite Micro memory constraints and heavily optimizing the FreeRTOS task scheduler, this firmware achieves **real-time bounding box tracking (15-20+ FPS)** for dynamic indoor emergency navigation.

---

## 🚀 The Engineering Architecture

Achieving real-time computer vision on a microcontroller with 512KB of internal memory requires strict architectural discipline. This firmware utilizes a highly optimized asymmetric dual-core execution strategy and aggressive memory manipulation:

### 1. Asymmetric Core Pinning
* **Core 0 (Networking & UI):** Dedicated to maintaining the Wi-Fi connection, handling the LwIP network stack, and serving the HTTP JPEG video stream. 
* **Core 1 (AI Inference Only):** Pinned exclusively to the Edge Impulse neural network loop (`run_classifier`). It runs uninterrupted, allowing the math to execute as fast as the hardware allows.

### 2. SRAM Eviction & Hardware Acceleration
To activate Espressif's **ESP-NN SIMD vector instructions** (which makes the AI run 3-4x faster), the AI's "Tensor Arena" *must* fit entirely inside the ESP32-S3's internal SRAM. 
To guarantee this space, this project utilizes **SRAM Eviction**. Through custom `menuconfig` directives, the entire Wi-Fi stack and HTTP server buffers are forcefully evicted into the slower external PSRAM, reserving a massive, contiguous block of ultra-fast internal SRAM exclusively for the YOLO model.

### 3. Client-Side Rendering
To prevent the ESP32's CPU from dying while trying to draw pixels on compressed JPEG frames, the firmware uses a split-payload approach:
1. Streams clean, unedited raw JPEG frames via an `<img>` tag.
2. Streams a lightweight JSON payload of `[x, y, width, height, label]` coordinates.
3. A JavaScript-powered HTML `<canvas>` runs on the *viewer's browser* to draw the bounding boxes seamlessly over the video feed.

## 🛠️ Hardware Requirements

* **Microcontroller:** ESP32-S3 (specifically boards like the **ESP32-S3-EYE** or ESP32-S3-WROOM modules).
* **Camera Module:** OV2640 (connected via standard 8-bit DVP parallel interface).
* **Memory:** Minimum **8MB External PSRAM** (Octal SPI highly recommended) and 8MB Flash.

Deployment & Compilation Guide
Step 1: Prerequisites
Ensure you have the ESP-IDF framework (v5.0+) installed and configured on your machine.

Step 2: Injecting the Neural Network
If you are updating the vision model, you must drop in the new C++ library from Edge Impulse:

Train a YOLO-Pro Pico model (160x160 Grayscale or RGB) in Edge Impulse.

Export it as an Unversioned C++ Library.

Delete the old edge-impulse-sdk, model-parameters, and tflite-model folders inside the components/ directory.

Extract your newly downloaded zip and place those three folders in their place.

Step 3: Critical Configuration (menuconfig)
WARNING: If you skip this step, the Tensor Arena will spill into PSRAM, disabling hardware acceleration and causing inference times to spike to 90+ seconds per frame.

Open your terminal and run:
idf.py menuconfig

Apply the following specific settings to enable SRAM Eviction:

Enable PSRAM malloc() Routing:

Navigate to: Component config ➔ ESP PSRAM (or ESP32S3-Specific).

Enable: Support for external, SPI-connected RAM.

Enable: Make RAM allocatable using malloc() as well.

Set: PSRAM clock speed to 80 MHz.

Evict the Networking Stack:

Navigate to: Component config ➔ Wi-Fi

Enable: Try to allocate memories of Wifi and LWIP in SPIRAM firstly.

Optimize the Compiler:

Navigate to: Compiler Options

Set: Optimization Level to Optimize for performance (-O3).

Save (S) and Quit (Q).

Step 4: Build and Flash
Clear the CMake cache to ensure the new memory map applies, then compile and flash to the board:
idf.py fullclean
idf.py build flash monitor

Operating the Vision Node
Once flashed, watch the serial monitor (idf.py monitor).

The ESP32-S3 will boot, allocate the PSRAM buffers, warm up the camera sensor, and connect to Wi-Fi.

Look for the output: Server up — open http://192.168.x.x/ in your browser.

Navigate to that root IP address in your web browser.

You will see the A.E.G.I.S Vision interface loading the live stream. If objects matching your trained classes pass in front of the camera, hardware-accelerated bounding boxes will snap to them in real-time.

⚠️ Performance Tuning Notes
Watchdog Timers: Core 1 runs a highly aggressive while(1) loop. A vTaskDelay(pdMS_TO_TICKS(1)) is included at the end of the inference task to allow the FreeRTOS idle task to reset the watchdog timer. Do not remove this, or the board will crash.

JSON Bottlenecks: The DETECTION_THRESHOLD macro in main.cpp is set to 0.4f (40% confidence). Lowering this will cause the ESP32 to serialize and transmit excessive "garbage" guesses, bloating the JSON payload and slowing down the Wi-Fi task on Core 0.

Memory Copy Acceleration: The get_model_tensor_data utilizes a raw pointer cast and a hardware memcpy to rapidly shift data blocks to the tensor arena, bypassing iterative CPU bit-shifting.
